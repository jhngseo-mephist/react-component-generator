# Create PR

PR 생성 실행 주체는 반드시 서브 에이전트다. 부모 에이전트는 위임과 사용자 소통, 결과 전달을 담당한다.

## 위임

- 부모는 `collaboration.spawn_agent`로 작업 하나를 위임한다. 이 SKILL.md의 절대 경로, 저장소 경로, 사용자 요청, 알고 있는 base/head, 기존 승인 범위와 미해결 제약을 전달한다.
- 서브 에이전트는 이 파일을 직접 읽고 아래 절차를 수행한다. 이미 위임받은 서브 에이전트라면 다시 위임하지 않는다.
- 서브 에이전트 도구가 없으면 제약을 알리고 중단한다. 부모가 대신 PR을 생성하지 않는다.
- 필요한 사용자 질문은 부모에게 전달하고 응답을 기다린다. 부모는 결과를 받을 때까지 작업을 추적하고, 완료 후 PR 링크와 검증 결과를 전달한다.

## 저장소와 변경 확인

- 적용되는 AGENTS.md, 기여 지침, PR 템플릿을 읽는다. 저장소·인증 상태, 원격 저장소와 fork 관계, 현재 브랜치, 작업 트리, base/head와 커밋 차이를 확인한다. base는 사용자 지정과 프로젝트 기여 규칙을 우선하며 `main`으로 단정하지 않는다.
- 커밋이나 push 전에 대상 base/head의 열린 PR을 조회한다. 이미 있으면 링크를 반환하고 종료한다. 기존 PR 수정은 사용자가 요청한 경우에만 수행한다.
- 커밋되지 않은 변경과 기존 스테이징을 확인하되 임의로 포함하거나 되돌리지 않는다. 커밋이 필요하면 프로젝트의 커밋 절차를 따른다. 이 프로젝트에서는 인접한 [commit 스킬](../commit/SKILL.md)의 구체적 범위·메시지 승인 절차를 따른다.
- base 대비 PR에 포함할 차이가 없으면 중단하고 이유를 보고한다. 충돌이나 대상 저장소의 모호함이 있으면 이를 해결하기 전 게시하지 않는다.
- 현재 브랜치와 사용자 변경을 보존한다. 브랜치 생성이 필요하면 프로젝트 규칙을 따르고 기본 접두사는 `codex/`를 사용한다. force push, 이력 재작성, merge는 이 스킬의 범위가 아니다.

## 언어와 템플릿 선택

사용자 지정 언어를 우선한다. 그다음 대상 저장소의 CONTRIBUTING·PR 템플릿의 명시적 언어 규칙, 최근 유지관리자가 작성한 PR과 기여 문서의 주된 언어를 근거로 선택한다.

- 해외·국제 오픈소스로 영어 기여를 받는 프로젝트: [영문 템플릿](references/pr-template.en.md).
- 한국어로 협업하는 한국 프로젝트: [한국어 템플릿](references/pr-template.ko.md).
- 소유자 이름, 국가 추정, 사용자 대화 언어만으로 분류하지 않는다. 근거가 혼재하고 선택이 중요하면 부모를 통해 언어를 확인한다.

선택한 언어의 reference만 읽는다. 대상 저장소에 필수 PR 양식이 있으면 그 구조와 항목을 우선하고, reference의 작성 기준을 적용한다. 제목과 본문의 설명 언어를 일치시키되 코드·명령·고유명사는 유지한다.

## 작성과 생성

- 실제 base 대비 전체 diff와 커밋을 근거로 최종 변경의 목적과 결과를 작성한다. 관련 검증을 수행하거나 기존 실행 근거를 확인하고, 미실행·실패·검증 한계를 정확히 쓴다. 문서만 바뀌었다면 불필요한 앱 테스트를 추가하지 않는다.
- 생성 전에 저장소, base/head, 제목, 완성한 본문과 검증 결과를 검토 가능한 상태로 준비한다. PR 생성 요청은 해당 PR 게시를 승인한 것으로 취급하며 같은 범위에 대해 반복 확인하지 않는다. 추가 승인이 필요한 로컬 규칙이 있으면 준비를 마친 후 부모를 통해 요청한다.
- 원격 head가 없으면 게시에 필요한 일반 push만 수행한다. 기존 승인과 프로젝트 규칙을 따르며, 별도 push 승인을 요구하는 규칙이 있으면 부모에게 요청한다. 승인되지 않은 fork 생성이나 무관한 브랜치 push는 하지 않는다.
- 게시 직전에 대상 base/head의 열린 PR을 다시 확인해 작업 중 생성된 PR과 중복되지 않도록 한다.
- 사용 가능한 GitHub 연결 도구를 우선하고, 필요한 기능이 없으면 인증된 `gh`를 사용한다. CLI의 여러 줄 본문은 UTF-8 임시 파일로 작성해 `--body-file`로 전달한다. 저장소·base·head는 명시적으로 지정한다. draft 여부는 사용자와 프로젝트 지침을 따른다.
- 생성 결과가 불명확하거나 타임아웃이면 같은 base/head의 PR 존재 여부를 조회한 뒤 재시도를 판단한다. 인증·권한 오류는 반복 재시도하지 않고 보고한다.
- 생성 후 URL, 대상 저장소, base/head와 게시된 내용을 확인한다. 부모에게 PR URL, 선택 언어와 근거, 검증 결과, 남은 제약을 보고한다. 실패하면 실제로 수행된 push 등 외부 변경도 명시한다.
